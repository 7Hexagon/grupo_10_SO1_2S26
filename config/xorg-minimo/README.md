# Sesión gráfica mínima (20/11/2026)

En `Aegis-Auth-reparada-prueba`, después del snapshot `grub-disco-systemd-auditoria-8pass-pre-xorg-20261119`, se instalaron X.Org Server 1.21.1.24, Fluxbox 1.3.7 y XTerm 411. No se instaló un escritorio completo ni un gestor de acceso gráfico.

La sesión se inicia manualmente desde la consola local como root con `startx -- -nolisten tcp`. El archivo `xinitrc-aegis` abre xterm y ejecuta Fluxbox; `20-aegis-vesa.conf` selecciona VESA para la VM. La configuración anterior se conservó en `/root/aegis-xsession-config-backup-20261120`. Esta primera solución utiliza root local: no se comprobó una sesión gráfica sin privilegios, y no debe interpretarse como una configuración multiusuario endurecida. No se habilitó X por TCP.

Se instalaron protocolos y bibliotecas X11/XCB; FreeType 2.14.3, Fontconfig 2.18.3, libdrm 2.4.134, Pixman, libxcvt, xkeyboard-config, xkbcomp 1.5.0, xauth 1.1.5, xinit 1.4.4, libevdev 1.13.6, mtdev 1.1.7, los controladores evdev 2.11.0 y VESA 2.6.0, fuentes DejaVu 2.37 y luit 20250912. Se compilaron sin aceleración 3D ni GLX/DRI en el servidor. libdrm fue necesario para cabeceras de compilación aunque DRM está desactivado en el servidor.

Las pruebas de Xorg informaron 5 PASS y 1 SKIP (XTS externo ausente). Las pruebas de libevdev no se ejecutaron por falta de Check. Fluxbox se compiló desde el tag oficial Release-1_3_7, commit `88a74ff1cde22be3e894498ffd88934dc92dfef0`; se corrigió en el árbol compilado una comparación de puntero incompatible con GCC 16 (`text_prop.value > 0` por `text_prop.value != nullptr`). El primer intento de instalación de Fluxbox falló; se reanudó ese componente, sin repetir las demás compilaciones.

Se inició Xorg con Fluxbox y xterm, se ejecutaron `uname -r`, `hostname` y la lectura de `/proc/1/comm`; la captura `evidencias/parte1/xorg-20261120/fluxbox-xterm.png` muestra las salidas. Se cerró la sesión terminando Fluxbox y se volvió a la consola. Durante el cierre aparecieron mensajes de desconexión de xterm y una advertencia MTRR de VESA; Xorg informó terminación correcta. Queda pendiente comprobar el cierre mediante el menú de Fluxbox y una sesión gráfica de usuario sin privilegios.

Después, systemd informó `running`, cero unidades fallidas y los servicios networkd, Dropbear, journald y aegisd activos. SSH de administración siguió funcionando y root fue rechazado por SSH. aegisd rechazó una autenticación inválida. La auditoría v1.1, sin modificar controles, produjo PASS=8, FAIL=0, WARN=0, igual que tras GRUB; informe: `auditoria/systemd-recuperada/aegis-audit-post-xorg-20261120.txt`, SHA-256 `4a2d94343a56a91e20ed61cadbfd86295153937722e1b260a478e1b13f148106`. La persistencia de la instalación tras otro reinicio no se comprobó en esta sesión.
